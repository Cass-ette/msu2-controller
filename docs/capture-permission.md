# Mac 投屏权限引导

## 问题与行为

之前投屏只调用 `CGPreflightScreenCaptureAccess` 查询权限，未授权时在主窗口状态栏显示文字，要求用户手动寻找系统设置，程序没有触发授权或提供跳转按钮。

构建 `20261113.4` 在实际投屏被拒绝后，将错误交回 Tk 主线程。每次应用运行最多自动调用一次 `CGRequestScreenCaptureAccess`；若系统当场授权，恢复本次画面请求和原来的实时更新状态。macOS 对已经拒绝过的应用可能不再弹出原生提示，此时显示独立的权限引导窗口：

- 「打开系统设置」直接进入屏幕录制页，部分系统名称为「屏幕与系统音频录制」。应用版显示需要开启「MSU2 小屏控制器」，源码版提示实际运行的终端或 Python。
- 「已开启，重试」再次检查权限，未通过则保留窗口与说明；通过后发送当前画面，并恢复本次请求前的实时更新状态。若系统要求退出并重新打开，应遵循系统提示。
- 「稍后」或关闭窗口保持投屏暂停，不会反复弹出；下次明确尝试投屏可以再次打开引导。

窗口不锁定主界面或串口工作线程；按键和空闲保活仍可运行。切换模式会关闭引导，已经过时的权限错误不会弹窗或暂停新模式。诊断工具仍只查询权限，不会主动请求。应用不能代替用户拨动系统权限开关。

## 实现与平台

`platform_support.py` 集中封装原生权限请求和设置深链，`features.py` 区分权限错误与其他截屏错误。共享 `app.py` 按请求身份处理错误；`capture_ui.py` 提供恢复窗口。Windows 保持原来的 Pillow 截屏路径，不调用 Mac 框架或打开 Mac 设置。没有新增依赖，没有更改串口协议、闪存流程或界面方向。

打包编号在 `MSU2Controller.spec` 与 `build_mac_app.py` 更新；`validate_bundle.py` 增加权限窗口的独立运行时检查。测试位于 `test_capture_permission.py`，原文案测试改为验证权限错误类型。

## 验证

2026-11-13，Apple 芯片 macOS 27.2 / Python 3.13.12：完整 163 项回归通过，7.371 秒。新增 11 项验证原生请求只在缺权时执行、仅自动请求一次、在 Tk 主线程显示窗口、设置深链使用参数调用、已授权重试会发帧、仍拒绝时不发帧、取消与模式切换、过期失败不干扰新模式、窗口期间串口工作线程可继续执行，以及 Windows 路径不进入 Mac 权限流程。

独立 arm64 构建通过内置 Python/Tk、中文字体 PingFang SC、权限窗口、图片取景、动画资源、通知 HTTP 和功率检查。未在本轮写入闪存或执行硬件传图；此前的硬件验证保留在其他记录中。

权限允许/拒绝及重试测试使用模拟结果，未清空或重置用户真实 TCC 记录；真实系统原生首次授权和系统要求重启后的恢复尚未完成端到端人工验证。另已实际调用与按钮共用的跳转接口，并用系统设置界面确认直达本机「录屏与系统录音」页面，没有切换任何权限开关。

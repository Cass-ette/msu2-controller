# GUI 调度修复与实机对照

日期：2026-11-13。Windows 和 Mac 共用同一份 Tk 界面与单工作线程，本次修复到期任务的公平性、定时刷新节奏、结果回收及通知取消。Mac 同设备实测，在目标 10 FPS、启用实体按键轮询时，旧 GUI 约 8.1 FPS，新 GUI 约 10.0 FPS。

## 问题、方法和边界

旧版每 20 ms 检查一次任务，每 10 ms 回收工作结果。按键总排在显示前；如果界面处理间隔超过 30 ms，按键可能每次都到期，使画面长期得不到发送机会。下一帧从实际请求时间重新加间隔，也会累计调度延迟。另一个问题是通知渲染期间切换模式或取消通知，旧通知仍可能被发出。

现在按截止时间选择到期的动态画面和按键，手动待发画面优先；完成一项任务后唤醒调度，定时器按下一个截止时间安排且各只保留一条。刷新沿原节奏推进、跳过已经错过的时刻，至多生成一个当前帧；不会积压旧帧或补发一串历史画面。API 开启时最多 20 ms 检查新通知，其他空闲状态最多 50 ms 检查。通知在渲染前后及回收时检查当前任务身份，取消后不再发送。

烧录和编辑器期间的互斥、唯一串口工作线程、空闲保活、设备方向和正向预览仍保留。投屏可选 2/5/10 FPS，默认 5；时钟、电脑状态、功率约每秒生成画面，数据采集频率不因调度修复而提高。本次没有新增依赖、系统分支或串口协议修改。

## 实机比较

[benchmark_gui_refresh.py](../../../benchmark_gui_refresh.py) 运行真实 Tk 事件循环、App.request_frame、工作线程、预览回调及 ADC 轮询。输入改为合成移动白块，排除桌面采集权限和采集成本；硬件模式实际调用连接小屏的 Display.show / read_adc。没有写入闪存，也没有以自动恢复掩盖错误。

两版各运行约 12 秒，目标 10 FPS，按键轮询开启，同一块 160×80、协议 01 小屏。传输源码 SHA-256 相同，使用此前已经优化的 RGB565 / 编码器，因此本次比较隔离了 GUI 修改。

## 模拟设备下的界面繁忙对照

模拟设备固定每次显示等待 45 ms、每次 ADC 等待 2 ms，仍运行真实 Tk。分别每 1 ms / 50 ms 处理一次界面事件，每组约 6 秒。

| 界面处理间隔 | 旧版 帧数 / ADC | 新版 帧数 / ADC |
| --- | ---: | ---: |
| 约 1 ms | 48 / 94 | 60 / 117 |
| 约 50 ms | 2 / 101 | 30 / 29 |

50 ms 条件下新版画面和按键都持续前进；旧版出现只轮询按键、很少发图的现象。此处的传输是模拟等待，不是第二组小屏实测。四份原始数据以 simulated 命名，和硬件文件明确区分；没有根据最慢一组反推所有真实场景的速度。

JSON 的 P95 / P99 沿用原测试脚本的排序下标 `int((n-1)*p)`，不插值；中位数使用 `statistics.median`。50 ms 旧版只有两帧，按此前约定计算的耗时 P95 / P99 可能低于算术中位数，不能用这两个样本估计尾部延迟。

## 版本与复测

基线为 `1b801e7` 的完整根目录源码副本，不含 .git，因此旧文件 metadata 的 commit/dirty 为 null；文件哈希已与该提交核对。新版为 `1f21840`，包含 `7f7a76c` 调度修复及 API 唤醒补充，原始 metadata 为干净源码。共同传输哈希：`71c19b9fd6d5eee591bd3504532458002da16c0c05a94d1419dae4139b467e55`。系统、Python、依赖和界面源码哈希在每份 JSON 中；汇总与原始文件校验值见 [summary.json](summary.json)。

```sh
# 真实 Tk + 模拟设备，不需要串口。
python -B benchmark_gui_refresh.py --seconds 6 --output validation/gui-simulated.json
python -B benchmark_gui_refresh.py --seconds 6 --ui-step-ms 50 \
  --output validation/gui-busy-simulated.json
# 释放串口后运行；只发送合成实时画面。
python -B benchmark_gui_refresh.py --hardware --port /dev/cu.usbmodem实际端口 \
  --seconds 12 --output validation/gui-hardware.json
```

可用 --source-dir 选择基线；每次使用独立 Python 进程。Windows 换实际 COM 端口，在图形桌面中运行相同命令。不要同时打开占用同一端口的其他控制器。
